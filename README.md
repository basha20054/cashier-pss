# كاشير — Lord Cafe · نظام محاسبة وإدارة مطعم

نظام نقاط بيع ومحاسبة متكامل بواجهة عربية RTL مصمم للعمل على الهواتف، مبني على
**Next.js + PostgreSQL (Drizzle ORM)** مع TypeScript بأقصى صرامة.

## المبادئ المحاسبية المنفَّذة (مختبَرة آلياً)

| الضمانة | آلية التنفيذ |
|---|---|
| المبالغ الدقيقة | كل المبالغ أعداد صحيحة بالأجورات (1 ₪ = 100) — لا أخطاء فاصلة عائمة |
| طلب نشط واحد للطاولة | فهرس فريد جزئي في PostgreSQL: `orders_active_table_uq … WHERE status IN ('open','sent')` |
| منع فاتورة مكررة | `invoices.order_id` فريد + الإغلاق يعيد الفاتورة الموجودة عند إعادة المحاولة |
| منع دفعة/استرداد مكرر | `payments.idempotency_key` و `refunds.idempotency_key` فريدان؛ الواجهة تولّد UUID لكل محاولة وتحتفظ به عند تكرار النقر |
| رقم فاتورة متسلسل آمن | عدّاد `seq_counters` يُزاد بـ `UPDATE … RETURNING` داخل نفس المعاملة (قفل صف) |
| إصدار الفاتورة كوحدة واحدة | معاملة PostgreSQL: قفل الطلب `FOR UPDATE` → حساب المجاميع من **لقطات الأسعار المخزنة** → الفاتورة + البنود + إغلاق الطلب — الكل أو لا شيء |
| الأسعار من الخادم | سعر الصنف يُقرأ من قاعدة البيانات عند الإضافة ويُخزَّن كأمانة تاريخية — لا اعتماد على بيانات العميل |
| الخصم مُتحقق منه | لا يتجاوز مجموع الطلب المحسوب في الخادم |
| الاسترداد | مدير فقط + سبب إلزامي + لا يتجاوز صافي المدفوع + تسجيل في `audit_log` |
| الأدوار في الخادم | `manager` / `cashier` / `staff` تُفرض في كل مسار API عبر `requireRole` |
| سجل تدقيق | جدول `audit_log` يوثّق كل حدث مالي (فتح، إغلاق، دفع، استرداد، تعديلات) |
| المنطقة الزمنية | إقفالات اليوم محسوبة بتوقيت `Asia/Hebron` مع مراعاة التوقيت الصيفي |
| الضريبة | نسبة قابلة للتعديل من الإعدادات (افتراضي 0%)، تُخزن نسبتها لقطةً في كل فاتورة |

## التشغيل محلياً

```bash
npm install
npx drizzle-kit push        # تطبيق المخطط على PostgreSQL
npx tsx src/db/seed.ts      # بيانات أولية (مستخدمون + طاولات + قائمة)
npm run build && npm start  # إنتاج  (أو npm run dev للتطوير)
```

## الاختبار التكاملي

```bash
bash scripts/test-flow.sh   # 24 فحصاً حياً: مصادقة، منع تكرار، دفع جزئي، استرداد، ترقيم، تقرير
```

## التشغيل على الهاتف

1. شغّل الخادم على الشبكة المحلية: `npm run build && npm start` ثم افتح من الهاتف
   `http://<IP-الكمبيوتر>:3000` على نفس الـ Wi-Fi.
2. **التثبيت كتطبيق**: من متصفح الهاتف → «إضافة إلى الشاشة الرئيسية» (iOS: زر المشاركة؛
   Android: قائمة ⋮). سيعمل بملء الشاشة باسم وثيمة «كاشير».
3. للوصول الدائم خارج الشبكة: انشر على خادم بشهادة HTTPS ولا تعرّض PostgreSQL للإنترنت.

## ملاحظة بخصوص مشروع Supabase السابق (42P07)

إن ظهر `relation "restaurants" already exists` عند تشغيل `001` فمعناه أن الملف نُفّذ جزئياً
سابقاً. خطته غير محصّنة بـ `IF NOT EXISTS`. المعالجة الآمنة (لا `DROP`):

1. افحص ما وُجد فعلاً (قراءة فقط):
   `SELECT table_name FROM information_schema.tables WHERE table_schema='public'`
   و `SELECT proname FROM pg_proc p JOIN pg_namespace n ON n.oid=p.pronamespace WHERE n.nspname='public'`
2. نفّذ يدوياً الأجزاء الناقصة فقط من `001` ثم `002–006` بالترتيب، أو عِد كتابة `001` بأوامر
   `CREATE TABLE IF NOT EXISTS` / `CREATE OR REPLACE FUNCTION` بعد مطابقة المخطط القائم مع المطلوب.
3. لا تعِد تشغيل ملف كامل دفعة واحدة؛ نفّذه جزءاً جزءاً وراقب النتيجة.
4. فعّل RLS على كل الجداول وتأكد من `FORCE ROW LEVEL SECURITY` وعدم وجود سياسة `USING (true)` عامة.
